# 家庭資料授權與上線順序

## 資料邊界

`users/{owner}` 是本人專用的完整 profile。家庭關係不授予整份文件讀取權；匿名、未登入及其他帳號都不能讀。

每位家人的投影位於 `users/{owner}/shared_profile/{viewer}`：

- `version: 1`、`inviteId`：綁定已接受的雙向家庭關係，重新綁定不恢復舊授權。
- `consent`：姓名、email、電話、生日、性別、血型、身高、體重、慢性病、過敏逐項 boolean；只有 `true` 是同意。
- `values`：只含已選且私密 profile 有值的欄位。規則拒絕未知欄位、未選欄位及與來源不符的值。
- `records`：血糖、血壓、用藥資料各自 boolean；控制既有記錄／藥品集合的讀取。
- `updatedAt`：伺服器時間。

所有選項預設關閉。家庭設定儲存時，以交易讀取本人最新 profile 並整份替換投影；取消勾選後儲存即清除舊值。分享的是個人資料副本，編輯 profile 不自動更新，需再次儲存分享設定。記錄授權則允許讀取該類現有及後續記錄，直到撤回。

共享文件只能由本人授權，僅指定且有效的家人可以 get，不能列出其他人的投影。移除任一關係後，投影及記錄讀取立即 deny；本機家庭健康頁遇撤回、關係消失、帳號切換、快取或權限錯誤會隱藏舊資料。離線時不把快取視為已確認授權。

邀請只建立關係，不授予健康分享，也不複製姓名／email。邀請者以「家人」識別；email 僅用於指定收件者，不能公開列出邀請。新聊天使用一般「家人」名稱，不從對方私密 profile 補資料。姓名／email 全關仍可綁定與聊天。舊版聊天室中已存在的名字及對方先前保存的資料不會自動消失。

## 離線操作與登出

Firestore 原生 batch／update 的 completion 只在後端提交完成時回呼，離線可能一直 pending（現有 iOS SDK 的 `FIRWriteBatch.h`、`FIRDocumentReference.h` 及 Flutter bridge 已核對）。資料網路工作使用獨立的登入世代守衛，登出取消等待及舊結果，不加入 auth／憑證儲存序列；手動與 timeout 都能先完成真正 signOut。

移除、拒絕邀請及邀請建立改用有讀取前提的交易，不新增盲目的離線 batch／update／add。移除必須明確傳入畫面原 inviteId（含缺值），不能自動採用重綁的新版本；只有雙方仍缺版本的舊關係可被清理，缺值不授予分享。有效雙向關係須同版本，反向刪除必須與自己的同版本關係一同移除，反向文件已不存在時亦可清理自己的殘留關係。分享儲存亦讀取原投影版本，重試不能覆蓋較新的撤回；同 UID 重新登入仍是新世代。遲到 callback 不回報成功，過時／取消載入不覆蓋帳號變更提示。

取消 Future 不是撤銷伺服器交易：已接受的提交無法收回；尚未確認結果時應重新連線載入核對，而不是宣稱撤回／移除成功。交易讀取前提與世代檢查保護後续重試，但 fake／emulator 不能證明所有實際 SDK 斷線時序。舊版已排入 SDK 的離線寫入不由此修正自動取消，更新與重綁前須連線確認舊操作；本次未清除 SDK cache 或正式資料。

## 相容與部署審閱

此變更沒有正式部署或資料遷移。新版 App 與規則須一起安排上線，不能只將舊客戶端改為 owner-only 後假設流程可用。

1. 先在 localhost 模擬器驗證完整規則與新版客戶端；人工審閱規則、索引及使用自己的測試專案設定。
2. 準備並要求舊版更新，通知使用者家庭分享需重新逐項授權。舊邀請可建立關係，但不繼承其共享選項。
3. 在維護／受控切換時段啟用完整新規則並發布新版客戶端；規則切換前新版分享寫入會失敗，切換後舊版跨帳號 profile 讀取會被拒絕。沒有暫時開放私密文件的相容 fallback。
4. 舊關係須有有效、已接受邀請及雙向關係，否則重新綁定。缺投影顯示未分享；不批次複製舊 profile、不推定舊資料是同意。
5. 用虛構資料驗證邀請、聊天、每位家人不同選項、撤回、移除、重新綁定及兩裝置斷線重連。正式驗證另需授權，不能將本機測試當正式部署證據。

不需要新後端或付費服務。正式使用仍有 Firestore 讀寫／監聽費用：每次分享儲存的客戶端約讀五份文件、寫兩份文件；規則相依讀取、交易重試及即時監聽另計。本次只使用本機假資料，沒有產生正式用量。既有正式規則在實際切換前不會因本機改檔而自動變安全。
